# BizYako Security and Support Contrast Hardening

## Goal

Correct the low-contrast floating support controls and abrupt light-to-dark footer transition while establishing a strong, fail-closed production security baseline across the Vercel and Namecheap deployments.

No implementation may claim that the website is completely immune to attack. The release instead closes the concrete weaknesses found in the current code and adds layered controls, verification, and operational guidance.

## Visual Refinement

### Standalone support icons

- Keep the WhatsApp and assistant launchers as standalone glyphs with no circle, rectangular surface, visible border, or filled background.
- Increase the glyphs to 32px on desktop and 30px on mobile while retaining at least 50px transparent interaction targets.
- Use a fine light edge and a darker outer drop shadow on the SVG glyph itself so each icon remains visible over white, teal, and near-black sections.
- Increase the outline stroke weight slightly without changing the approved icon shapes.
- Preserve the animated assistant dots, floating position, keyboard focus state, tool labels, and open chat panel behavior.

### Section transition

- Preserve the existing light process section and dark contact/footer palette.
- Add a full-width transition band above the contact section that blends from transparent light teal into the contact section's dark teal.
- Keep content outside the transition band so text contrast remains stable.
- Use a shorter band on mobile to avoid consuming vertical space.

## Security Architecture

### Shared security module

Create a dependency-free Node security module used by the local/Namecheap server and Vercel API functions. It will provide password verification, signed sessions, CSRF validation, origin checks, request limits, security headers, upload validation, and security-event logging.

The module will read these server-only environment variables:

- `BIZYAKO_ADMIN_PASSWORD_HASH`: scrypt hash generated by a repository setup command.
- `BIZYAKO_SESSION_SECRET`: at least 32 random bytes encoded as base64url.
- `BIZYAKO_ALLOWED_ORIGINS`: comma-separated exact HTTPS origins for `https://bizyako.com` and `https://bizyako.vercel.app`, plus localhost only in development.

Missing or malformed production variables must lock administrative actions while leaving the public website available. No default password, plaintext credential, session secret, or reusable token may exist in tracked source.

### Administrator authentication

- Add one same-origin `/api/admin-auth` endpoint supporting login, session inspection, and logout.
- Verify passwords with Node scrypt and constant-time comparison.
- Issue a signed, stateless, 30-minute administrator session in an `HttpOnly`, `Secure`, `SameSite=Strict`, host-only cookie.
- Rotate the signed cookie after successful authentication and clear it on logout or invalid verification.
- Return generic login errors that do not reveal whether configuration, password, or account state failed.
- Limit login attempts to five per 15 minutes per privacy-preserving IP fingerprint and add increasing response delay after repeated failures.
- Emit structured audit events for login success, login failure, throttling, logout, rejected origin, and carousel writes without logging passwords, tokens, image data, or full IP addresses.

### Admin interface and authorization

- Render a dedicated admin login view before loading or activating the editor.
- Keep the editor hidden and inert until `/api/admin-auth` confirms a valid session.
- Require a valid signed session, exact allowed origin, and matching CSRF token for every carousel write.
- Store the CSRF token only in current page memory; do not use localStorage.
- Add logout and expired-session handling.
- Mark the admin page `no-store`, `noindex`, and exclude it from PWA caching.
- Keep Vercel carousel writes read-only after authorization because the Vercel function filesystem is not durable; allow authenticated writes on the Namecheap Node host.

### Upload and carousel validation

- Accept PNG, JPEG, WebP, and AVIF raster images only.
- Remove SVG upload support because uploaded active content can execute script in browser contexts.
- Limit each decoded image to 2 MB and the complete carousel request to 8 MB.
- Validate the declared data URL, decoded byte length, and file signature on the server.
- Permit committed paths only under `assets/` and optionally raster data URLs; reject JavaScript URLs, protocol-relative URLs, control characters, traversal, and unapproved remote hosts.
- Limit every carousel text field and URL field to explicit lengths, validate product IDs against the nine supported products, and keep the slide count at exactly one to five.
- Escape all carousel-driven DOM output and avoid inserting trusted-looking strings without encoding.

### Public form protection

- Reduce the contact request limit from 1 MB to 32 KB.
- Enforce JSON content type, same-origin requests, exact field allowlists, and explicit field lengths.
- Add an off-screen honeypot and minimum submission-time signal to reject basic automated spam without affecting keyboard or screen-reader users.
- Limit contact submissions to six per 10 minutes per privacy-preserving IP fingerprint.
- Return `429` with `Retry-After` when throttled and generic validation messages for malformed traffic.

### Browser and transport controls

Apply matching headers in `vercel.json`, the Node server, and the Namecheap `.htaccess` fallback:

- Content Security Policy with `default-src 'self'`, external Google font allowlists, same-origin scripts/workers/connections, raster image support, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, and `frame-ancestors 'none'`.
- `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, restrictive `Permissions-Policy`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-site`, and `X-Permitted-Cross-Domain-Policies: none`.
- Move service-worker registration out of inline HTML so the CSP does not require `unsafe-inline` scripts.
- Add `X-Robots-Tag: noindex, nofollow, noarchive` specifically to admin routes.
- Preserve HTTPS-only production hosting and document DNSSEC/CAA as hosting-account controls that cannot be guaranteed by repository code.

### Server hardening

- Replace string-prefix path checks with `path.resolve` plus a relative-path containment check.
- Reject null bytes, malformed URL encoding, unsupported HTTP methods, and unexpected content types.
- Set conservative request, header, and keep-alive timeouts.
- Avoid exposing stack traces, filesystem paths, tokens, or implementation details in responses.
- Keep sensitive and authenticated responses at `Cache-Control: no-store`.
- Add `.well-known/security.txt` with `hello@bizyako.com` as the security contact.

### Vercel firewall rollout

- Keep Vercel's automatic DDoS mitigation enabled.
- Stage generous monitoring-only firewall rules for login and public form endpoints.
- Do not publish blocking or rate-limiting rules automatically. Review matched production traffic first, test enforcement in preview, and require the owner to publish the final production rules.
- Retain in-application limits because Namecheap does not share Vercel's firewall.

## Verification

- Use TDD for every authentication, session, CSRF, validation, upload, rate-limit, path-containment, and security-header behavior.
- Verify tests fail for the expected missing control before production implementation.
- Run the full Node test suite, JavaScript syntax checks, and `git diff --check`.
- Run local end-to-end checks for failed login, successful login, session inspection, CSRF rejection, authenticated save, logout, contact throttling, malicious upload rejection, and traversal rejection.
- Verify desktop and mobile computed icon contrast, transition geometry, chat behavior, and zero horizontal overflow.
- Deploy to Vercel, inspect the production deployment, verify all response headers and protected admin behavior, then prepare a matching Namecheap Node package and configuration checklist.

## Operational Requirements

- Generate credentials locally and place them only in Vercel and cPanel environment settings.
- Document initial setup, password rotation, session-secret rotation, emergency lockout, and firewall publishing.
- Require credential rotation after any suspected exposure and at regular operational intervals.
- Keep GitHub secret scanning enabled and run the full security regression suite on pushes and pull requests.
